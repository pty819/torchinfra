# 模型代码审计报告 (2026-11-20)

背景: 用户质疑 compile 死机与模型代码有关。逐项对审 sdcpp 源码后的结论。

## 核对无误 (6项)
timestep MLP 双 silu / RMSNorm eps 1e-6 / 无参 LayerNorm / patchify (c,ph,pw) 通道主序 /
attention scale 1/sqrt(d) (kv_scale=1.0 是缓存缩放) / sigma 公式与调制门控

## 发现并修复 (3项)
1. **rope 坐标系错误 (语义级)**: 误照 diffusers 1.0 移植。2.1 真实坐标系 (sdcpp
   QwenImage21Layout.build): text j→(j,j,j) 从0起; image (h,w)→(L_txt, h-(H-H//2), w-(W-W//2))
   中心化, t 轴=文本长度。已重写 build_rope。
2. **gelu 变体**: ggml_ext_gelu 是 tanh 近似, F.gelu 默认 erf。已加 approximate="tanh"。
3. **compile 死机的代码侧放大器**: FP8Linear.forward 内 try/except 造成 dynamo 逐层图断裂
   → 229 层反复重编译 → 内存/时间爆炸 (与 inductor 多 worker 叠加压死 30GB RAM)。
   已改为 __init__ 一次性能力探测, forward 无 try。compile 复跑时仍须 TORCHINDUCTOR_COMPILE_THREADS=2。

## 探针自身的两次假阳性教训 (连环坑)
- 探针形状 N=2 非法 → 全层静默退化 bf16 反量化 (0.35→0.62 s/步, 慢 1.8x)
- 探针多余 .contiguous() 破坏列主序 → rowwise 拒绝
- 修复后单测新增 assert lin.fp8_ok — 退化路径必须让测试红, 不许"自测自过"
